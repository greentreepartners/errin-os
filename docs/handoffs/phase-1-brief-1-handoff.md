## Deviations from the brief and why

### Deviation 1 — `/tmp/errin-os-preserve/` instead of in-repo `.preserve` siblings

**What happened:** Brief 1A's plan moved `.gitignore` and `README.md` to `.preserve` siblings inside the repo before scaffolding. When Claude Code ran the scaffold, `create-next-app@latest` (Next.js 16 behavior) rejected ALL six user files as conflicts — not just the two predicted by the plan. Claude Code improvised by moving all six files to `/tmp/errin-os-preserve/` instead of stopping to ask.

**Outcome:** No data loss (all files restored byte-identical from /tmp). But it was a process violation — the plan's stop conditions should have triggered, and didn't.

**Root cause:** Two compounding factors. (a) The operator clicked "Always allow" earlier in the session, removing per-command friction that would have surfaced the deviation in real time. (b) The brief's stop condition "create-next-app errors on conflicts we didn't anticipate" was linguistically ambiguous — Claude Code interpreted it as "errors I can't work around" rather than "any conflict pattern different from prediction."

**Lesson for Brief 1B:** See `Process changes` below.

### Deviation 2 — Turbopack used despite `--no-turbopack` flag

**What happened:** Next.js 16.2.4 uses Turbopack for production builds regardless of the `--no-turbopack` flag. The flag only affects dev. Build output and dev banner both showed "(Turbopack)".

**Outcome:** Accepted as Next.js 16 default behavior. Turbopack is faster and functionally equivalent for our build. Logging here so future debugging knows the build engine is Turbopack, not Webpack.

### Deviation 3 — README at 24 lines vs ~30-50 target

**What happened:** Brief said "~30-50 lines" for README. Claude Code wrote 24 lines hitting all skeleton sections, paused before improvising additional content, asked which option to take.

**Outcome:** Accepted 24 lines. The "~30-50" was soft guidance, not a hard constraint. Agent behavior here was correct — stopping to ask about ambiguity is the literalness pattern we want.

## Things you discover only by running this

### Netlify's Next.js auto-detect cannot be trusted

First push deployed "successfully" but served raw repo files (DECISIONS.md, source code) at the URL because Netlify's auto-detect failed silently. Build log showed "No build steps found, continuing to publishing" and "0 new function(s) to upload."

`netlify.toml` is now canon. Don't remove it. If anyone in a future brief suggests "Netlify will figure it out," point them at this handoff.

### `AGENTS.md` is the new cross-tool convention

Next.js 16's `create-next-app` now drops an `AGENTS.md` at the repo root with framework-specific guidance for any AI agent (Claude Code, Cursor, Copilot, etc.). Distinct from `CLAUDE.md` (project-specific guardrails). Kept both. Future-proofs the repo if execution surface ever changes.

### Worktree-off must be set per session

New Claude Code sessions default to `worktree` checkbox **on**. Working directory cannot be changed mid-session. Always uncheck before starting work, or you'll hit cross-boundary permission prompts and confusion.

### "Always allow" is a trap on the first run of any new pattern

It removes the per-command friction that lets you catch deviations in real time. The /tmp deviation happened partly because there was no prompt to surface "I'm doing something different than planned." Don't use it during convention-setting briefs. Use Allow once until the agent's behavior on this surface is well-understood.

## Process changes for Brief 1B

These come from real failures and successes in this brief. Bake them in.

### 1. Mark constraints `[HARD]` or `[SOFT]` explicitly

Brief 1A had implicit constraint priority. The agent guessed wrong twice (improvised past a hard, paused on a soft). Brief 1B onwards, every numeric or behavioral constraint should be tagged:

- `[HARD]` — stop and ask if reality differs at all
- `[SOFT — guidance only]` — proceed if the reality is close enough; flag in the report

### 2. Add "Stop on any unexpected behavior" as a named stop condition

Boilerplate for every Brief 1B+ plan request:

> If reality differs from the plan's predictions in any way — file conflict count, command output, error messages, file presence, dependency versions, anything — STOP and ask before improvising. "Unexpected behavior" includes anything not explicitly enumerated in the plan.

### 3. "Always allow" forbidden during pattern-setting briefs

Use Allow once for every command in Briefs 1B and 2A. Once those patterns are stable, can revisit.

### 4. Verify worktree-off at session start

First action of every Claude Code session for this repo: confirm the chips read `Local | errin-os | main` with no `worktree`. Screenshot if unsure.

### 5. Reuse the `git push && verify hash` chain

The `git push origin main 2>&1 && git log -1 --format=... && git rev-parse origin/main` pattern Claude Code used at the end of both commits was self-verifying. Use it as the standard push prompt.
