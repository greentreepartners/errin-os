Three candidate conventions drafted this session (PM-drafted per precedent posture, awaiting Strategy approval at next escalation):

1. **Per-step gate invariance.** Commit, push, and verify are always separate permission gates. git add staging also requires a visible gate. Discipline doesn't relax for smaller commits or follow-up work — the second commit of a session gets the same scrutiny as the first.

2. **Permission-dialog redirect protocol.** Permission dialogs in Claude Code are deny/allow only. To redirect or query the agent mid-execution, deny the dialog first to return control to the main input, then send text guidance there. Never attempt to type instruction while a dialog is the active modal.

3. **Parser-clean chain rule.** The chained-command rule extends beyond parser warnings (the existing `&` backgrounding rule). A single permission gate covering multiple consequential operations (file mutations, network actions, irreversible state changes) must be denied even if the chain parses cleanly. Test isn't "does the dialog warn" — it's "how many things would I be approving with one click."

Runtime `process.env.X` inside Netlify's serverless function does not see build-only vars. Webpack DefinePlugin via `next.config.ts` `env: {}` is the correct surface. Worth codifying when DECISIONS.md opens for Phase 2.
- The `||` vs `??` empty-string lesson for DefinePlugin-inlined env vars: when `next.config.ts` substitutes `process.env.COMMIT_REF ?? ""`, an unset var becomes the empty string at build time, and `??` does not fall through on `""`. Use `||` to guard the primary lookup, `??` only for the null/undefined fallback chain. Patched mid-review this session.
